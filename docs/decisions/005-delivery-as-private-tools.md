# 005 · 定制需求的交付物直接进工具一览，默认只有提需求的人看得见

> 日期：2026-09-09 · 决策人：大海（方向与口径）/ 执行：Claude + 灵犀评审 · 状态：P0 已上线

## 触发

- [x] 主动改进（大海直接提的需求）

原话：「我要改需求的交付方式，交付的产品直接发布在工具一览里，只是可见只能是提需求者，
他可以选择是公开还是私有，默认交付是私有」；随后补了三条：
「交付我不介入，让灵犀上交付工具一览，如意告诉客户」「交付物得包含在线、视频和下载 3 样全」
「公开不需要审核」。

## 现状（改之前的可观测量）

- 交付 = 站长把文件传到 `uploads/deliverables/`，**私信发个链接**给客户。
  客户拿到的是一条会沉底的消息。
- **结单闸门是字符串匹配**：`TicketsController.cs` 查"发给客户的私信里含 `deliverables` 字样"。
  只要私信里出现过这个词就算交付了。
- `Tools` 表**没有归属概念**：103 个工具全是站方的，`/api/tools` 完全公开、不看身份。

## 决定

### 1. 交付物 = 工具一览里的一个工具（归属客户，默认私有）

`Tools` 加三个字段：`OwnerUserId`（null=站方工具，现存 103 个都是）、
`Visibility`（public/private）、`SourceTicketId`（交付溯源）。

**可见性判定只写一处**（`ToolsController.Visible()`），列表 / 详情 / 下载 / 在线 /
视频 / 分类计数全部走它。判定散在各处的话，迟早漏一处，而漏掉的表现是
「本该只有客户看到的交付物挂在首页上」——这种错误不会报警，会一直存在。

### 2. 私有靠访问控制，不靠"没人知道路径"

交付物放 `uploads/private/<工单号-随机串>/`，**静态层对这个前缀一律 404**
（沿用 qianky 那页的成法）。唯一入口是三个接口：

```
GET /api/tools/{slug}/online     在线版本体（iframe 指它）
GET /api/tools/{slug}/video      讲解视频（支持 Range，进度条能拖）
GET /api/tools/{slug}/download   下载包（既有接口，加归属校验）
```

**故意不做成 `/file/{*path}`**：路径只从工具自己的字段来，请求方连"读哪个文件"
都决定不了，路径穿越那条攻击面根本不存在。代价是私有交付物只能是
「单文件网页 + 一个下载包」，多文件网页的相对引用取不到。

**数据库里存真实路径**（`/uploads/private/...`），只在接口出口换成鉴权地址。
这样后台「文件是否在用」的扫描照常认得它们——否则三个交付文件会被判成空闲，
被「一键清理空闲文件」删掉。

### 3. 公开与否由客户自己定，不审核

`PUT /api/tools/{slug}/visibility`，只有归属人（和站长）能改。
公开就是**真公开**，和站方工具一视同仁（进列表、进分类计数、进搜索）——
不搞"公开了但不进热门"这种暗规则。站长后台随时可以改回私有或下架。

### 4. 交付链路里没有大海（P1，待做）

| 角色 | 干什么 |
|---|---|
| 威震天(22) | 产出交付物本体：**在线版 + 下载包** |
| tool-video 产线 | 出**视频讲解**（第三样） |
| 灵犀(20) | 三样齐了才上架：建工具行、归属客户、默认私有 |
| 如意(23) | 唯一对客户说话的：告诉他交付好了、在工具一览里、怎么切公开 |
| 大海 | 不介入。同一工单连挂两次、灵犀处理不了才升级 |

**「交付完成」的定义变成机器可判的五条**：归属人是客户、private、在线版能开、
下载文件在磁盘上、视频能被 ffprobe 读出两条流。少一样不算交付，工单结不了单。
这会替换掉现在那个"私信里含 deliverables 字样"的闸门。

## 备选方案与放弃理由

- **交付物做成单独的「我的交付」页面。** 否决：大海要的是"直接发布在工具一览里"——
  客户不需要学一个新地方，他的东西和站方工具在同一个列表里，只是别人看不见。
- **公开要站长审核。** 否决：大海明确"公开不需要审核"。代价是客户可以把内容推到
  站方门面上，缓解靠"站长可一键收回"。
- **私有靠随机路径（不做访问控制）。** 否决：那不叫私有，叫没人知道；
  而路径会出现在浏览器历史、日志、转发的链接里。
- **`/file/{*path}` 通用取文件接口。** 否决：多一个路径参数就多一条要自己防穿越、
  防越权的路。用固定的 online/video 两个入口，攻击面直接消失。

## 风险与代价（这个改动让什么变差）

1. **多了一条鉴权路径就多一处可错**。归属校验漏一个分支就是别人的交付物被下走。
   已用 `evolution/experiments/tool-private-visibility/` 的 30 项实测覆盖四个身份，
   并送灵犀对抗性评审。
2. **私有是访问控制，不是加密**。站长能看全部（不然没法排查），文件在服务器上是明文。
3. **私有交付物只能是单文件网页**，多文件网页要等 `/file/{*path}` 那套（暂不做）。
4. **P1 上线后是无人复核的自动上架**：AI 产出的东西直接进客户账号。
   缓解靠默认私有 + 三样机器校验 + 如意通知里带"有问题回我"。

## 上线当天评审抓到的三条（已修，commit 8b13ca8）

1. **后台点一下「上架」，客户的私有交付物变成站方公开工具**。`UpdateTool` 无条件覆写
   归属，而后台前端的 `toBody()` 根本不带这三个字段。改成「字段缺省就不动归属」。
2. **收藏接口整个绕过可见性判定**：遍历 id 收藏一遍，收藏页就吐出全站私有交付物的
   名字和简介。判定因此抽成 `Services/ToolVisibility.cs` 全站唯一一份。
3. **`//uploads/private/x` 能绕过静态拦截**——实测直连和线上都返回 200 并吐出内容。
   `StartsWithSegments` 对 `//uploads` 返回 false，而静态文件提供程序会把前导斜杠
   `TrimStart` 掉照样找到文件：**一道拦截和一个文件提供程序对"同一个路径"的理解不一样，
   中间那条缝就是洞**。同一招也绕过 qianky 那页的 404。
   修法两层：管道最前面塌掉重复斜杠 + 拦截判据从前缀字符串改成按段比较。

> 第三条评审时判的是 PLAUSIBLE（认为 nginx 的 `merge_slashes` 兜着），
> 实测发现 nginx 没兜住。**"大概有别的东西挡着"不能当结论**——curl 一次就知道了。
