# 004 · 工具增加「视频讲解」动线，并把 103 个工具的文件按中文文件夹归置

> 日期：2026-09-08 · 决策人：大海（方向）/ 本次执行：Claude · 状态：已上线

## 触发

- [x] 主动改进（大海直接提的需求）

大海要两件事：工具详情从「在线使用 / 下载」两个入口改成「在线使用 / 视频讲解 / 下载」
三个入口；工具文件从平铺改成一工具一文件夹，文件夹名支持中文。
路线由大海拍板：**弱约定（A）** + **老工具全量迁移（P2）**，顺带把不好的文件名一起改。

## 现状（改之前的可观测量）

- `uploads/` 根目录平铺 **116 个文件**，只有 `lib/ zip/ cg-offline/` 三个零散子目录。
- **103 个工具**（100 个有在线页、33 个有下载包、54 个收费），文件名从
  `BatchPerformanceAnalyzer_20260707023857.html`、`mcp-tool-generator-337335206301d18f.zip`
  到 `dbyd.html` 都有，看名字认不出属于哪个工具。
- 没有任何视频字段；讲解只能写在说明文档里。

## 决定

### 1. 视频讲解

`Tools` 加 5 个字段：`VideoUrl`（非空即"有讲解"）、`VideoSource`（upload/link，
由 URL 形态推出，不让前端填）、`VideoDuration`、`VideoPlayCount`、`Folder`。

**不设 `HasVideo` 布尔**——`HasDownload`/`DownloadFileName` 这对字段已经证明
两个字段会互相打架（勾了没传文件、传了没勾），前台就白按一次。

讲解一律公开，不跟 `RequireLogin`/`IsPaid` 挂钩：让人看懂再决定买，付费墙留在下载那层。

站内视频走 `<video>`（静态中间件原生支持 Range，可拖进度条），B 站/YouTube 外链内嵌
对应播放器，认不出的站点开新标签页。上传单开端点
`POST /api/admin/tools/video-upload`（500MB，nginx 同路径放宽），
只收 mp4/webm。

### 2. 一工具一文件夹

`uploads/tools/<工具名>/`，工具名原样做目录名（中文），
文件名 = 文件夹名 + 原扩展名，视频统一叫 `讲解.mp4`。

路径仍**完整存在** `OnlineUrl`/`DownloadFileName`/`VideoUrl` 里，不靠 `Folder` 拼——
`Folder` 只是「新文件默认落哪 + 后台分组」的依据。

归置分 `plan`（只算不动）/ `apply`（照单执行）两个接口：
人先看清单、手工调掉不合适的几条，调完照单执行，**执行的和审过的是同一份**。

### 3. 老链接不断

新建 `UploadRedirects` 表，搬家时记旧路径→新路径；`Program.cs` 在 `UseStaticFiles`
之后拦 `/uploads/*` 的漏网请求，查表 301。
没有这段，老链接不会 404，而是落到 `MapFallbackToFile` 拿到 **200 的 index.html**——
比 404 更糟：下下来是个 HTML 首页，用户以为文件坏了。

## 备选方案与放弃理由

- **强约定（B）：DB 只存文件名，路径由 `Folder`+文件名拼。** 否决：现网已有
  `RewriteReferencesAsync` 这套「文件一动，全站引用自动改」的机制，弱约定直接复用；
  强约定要重写下载、引用扫描、空闲判定全部逻辑，且表达不了外链视频和 `lib/` 共享库。
- **只管新工具、老的不动。** 否决：大海明确要 P2 全迁。代价是有一次性断链风险，
  用 301 兜底 + 迁移前全量备份来消。
- **视频只允许外链（省磁盘和带宽）。** 未采纳为硬限制，但设计上鼓励：
  100 个工具 × 150MB ≈ 15G，会吃掉服务器剩余 30G 的一半。两种都支持，由大海按工具选。

## 风险与代价（这个改动让什么变差）

1. **磁盘/带宽**：站内视频每个工具上百 MB，只能靠人自觉控制，代码不拦。
2. **一次性大动作**：110 个文件移动 + 全站引用改写，出错面比日常改动大。
   已用「全量校验通过才开始搬 + 搬失败原样退回 + 数据库改写放在文件全搬完之后」压住。
3. **文件名规则会咬人**：目录名不能带空格/`()[],;?#%`——不是审美，
   全站扫引用以这些字符为边界，带了就会把引用截断，**文件会被判成空闲、被一键清理删掉**。
   103 个工具里 74 个名字带空格，因此自动生成的文件夹名把空格压成连字符
   （`PDF 转换工具` → `PDF-转换工具`）。
4. 归置操作对「已经在自己文件夹里」的文件一概不动，否则人工特意保留的名字
   （歌名、APK 的 ABI 号）会在下次点按钮时被悄悄改回工具名。

## 验证方式（判据先写死，实测结果在后）

1. 迁移前后 uploads 文件总数不变，且每个搬过的文件与备份逐字节哈希一致。
   *实测：116 → 116；110 个文件哈希全等，唯一内容变化是 CodeGraph 离线页里
   那条指向自己安装包的内部链接被改写（预期内）。*
2. 数据库里每条 `OnlineUrl`/`DownloadFileName`/`VideoUrl` 在磁盘上都找得到。
   *实测：103 个工具仅 1 条坏引用，且是迁移前就坏的
   （微软生成式AI课程的 `zip/generative-ai-beginners.zip` 早已不在磁盘上）。*
3. 后台文件列表里没有文件被误判成空闲。*实测：116 个文件，空闲 0。*
4. 老链接 301 到新地址且最终 200。*实测：`/uploads/pinyin-learning.html` → 301 →
   编码后的新中文路径 → 200。*
5. 真浏览器（390px 手机宽）实访：三个标签不溢出、三个按钮都在、视频真的在播
   （`readyState=4`、`currentTime` 走动）、无 console 报错、无失败请求。
   *实测全通过；播放计数 +1 生效。测试用的自检视频与临时上架已还原，站上无残留。*
6. 归置幂等：再跑一次 plan 应为 0 个移动。*实测：0。*

## 顺带修掉的既有问题

- `/api/admin/upload` 从来没有 `RequestSizeLimit`/`RequestFormLimits`，
  Kestrel 默认 ~28MB 就截断，代码里那句「不能超过100MB」根本轮不到执行。
- 下载响应的 `Content-Disposition` 会把带子目录的路径整个当文件名，现改为只取文件名。
- `Upload.jsx` 显示上传结果读的是 `data.filename`，后端返回的是 `fileName`，
  一直显示 undefined。
