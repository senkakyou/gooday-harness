# 001 · 把本骨架开源为工程模板

> 状态：**已定方向，未启动**（2026-09-07 定）
> 决策人：站长 · 记录人：Claude

## 目标

把这套骨架（`AGENTS.md` + `policies/` + `checks/` + `ops/` 结构）开源，
做成**别人可以整套套用的 AI 工程骨架模板**。

Gooday 本体（网站、bot、内容产线、业务数据）**保持私有**，
作为这套骨架的**参考实现**——也就是"揍过它的那个现实"。

## 为什么是这个，不是别的

站长手上最独特的资产不是那个 CRUD 网站，是**被真实事故揍出来的 AI 工程规范
＋ 能自动跑的检查器**。

市面现状（2026-09 核实）：

- `AGENTS.md` 已是成熟标准（Agentic AI Foundation / Linux 基金会托管，
  6 万+ 仓库，30+ 工具原生读取）——**这部分不用我们发明**。
- 通用检查有成熟工具：gitleaks / TruffleHog / Semgrep / pre-commit。
- **但"规范自带检查器 + 每条规范附换来它的那次事故"这个组合，没有成熟项目在做。**

这就是空位。

## 判据（可证伪，不达标就该废弃或重做）

1. **开源后 90 天内，≥3 个非本公司仓库接入并跑过 `evolution/gates/check.py`**
   —— 拿不到就说明它只对我们自己成立，不具备通用性。
2. **接入方 30 天内至少有 1 次 CI 因本检查器变红并被真正修复**
   —— 一次没红过，说明检查器太松，等于没接（沿用 harness-kit 的判据）。
3. **每条规范都能指出换来它的那次具体失败**
   —— 指不出来的条目，说明是抄来的教条，应当删除。

三条任一连续两个季度不达标，**这套模板应当被废弃或重做**。

## 开源前必须解决的四件事（尚未决定）

| # | 事项 | 现状 | 影响 |
|---|---|---|---|
| 1 | **脱敏** | 规范里带着灵犀/如意/大海/工单号/金额 | 教训是卖点、业务细节是风险，**必须逐条过**，不能整体删 |
| 2 | **LICENSE** | 未定 | MIT（最宽松、传播快）vs Apache 2.0（带专利授权） |
| 3 | **语言** | 全中文 | 只面向中文社区就保持；要国际影响力需双语，是持续维护成本 |
| 4 | **与私有 Gooday 的关系** | 未定 | submodule / 定期同步 / 两个独立仓库各自演进 |

> 第 1 条是最难的：**"真实教训"正是这套东西的灵魂**
> （harness-kit 自己的 README 就写着"每条硬约束后面都附了换来它的那次失败"）。
> 抽成占位符抽狠了，规范就退化成教条；抽轻了会泄业务。得一条一条判。

## 不做什么

- **不开源** Gooday 的应用代码、bot 的 system prompt 实体、内容产线、任何业务数据。
- **不承诺**兼容性或支持窗口。这是模板不是库，使用者应当 fork 后自行演进。
- **不为了显得通用而删掉具体教训**——见判据 3。
