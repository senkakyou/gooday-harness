## 两条豁免，写明理由

`content/` 在两条检查规则里有作用域豁免，**都不是"算了不查了"**：

- **G09 路径全 ASCII** —— 稿件文件名本身是作品的一部分（`序寂·六卷全本.txt`、
  `投稿短篇.docx` 是要交出去的东西）。豁免的**前提是工具链真的扛得住**：
  迁入当天验证了 `check.py` 的 `tracked()` 能按名打开全部 12 个中文路径，
  并当场修好了 `g20 --fix`（它自己拼 `git ls-files` 没带 `core.quotepath=false`，
  一碰中文名就崩 —— 正是 G09 那条教训记录的同一个坑）
- **G03 同名文件** —— 六本书各有 `ch01.md`…`ch10.md`，是结构性重名不是副本。
  **只豁免这一项**：`.bak` 手工备份、汇总产物那几条对 `content/` 照查不误
  （已实测：往这里放一个 `.bak` 仍然报 ERROR）

## 判据

1. **迁入后与源逐字节一致** —— 迁入当天 92 个文件 md5 全数比对通过。
2. **格式化不得改动一个字** —— `g20 --fix` 只加空行、去行尾空格；
   迁入时对 74 个被改文件做了「去掉所有空白后哈希比对」，92/92 内容零变动。
3. **这里的东西必须在 GitHub 上有副本** —— 它没有第二个备份了。
   本地删除前必须先确认 `git push` 已落地。
