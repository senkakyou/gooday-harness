## 验证方式

只能实测。这条链路上有四个判定（收款、三样齐、归属对、通知幂等），
任何一个"看起来对"，实际表现都是**客户拿不到东西**或者**账对不上**。

```bash
# 先造三样文件
D=/srv/gooday-harness/media/uploads/private/GD-TEST-DELIVER
mkdir -p "$D" && echo '<h1>自检</h1>' > "$D/交付物.html" \
  && cp /srv/gooday-harness/media/tool-video/_selftest/selftest.mp4 "$D/讲解.mp4" \
  && echo payload > "$D/交付包.zip"
python3 evolution/experiments/ticket-delivery-flow/check.py
```

脚本跑完自己清理：工具、文件、财务记录、项目、子任务、工单、测试私信。
**清理只删自己造的那几条**——尤其私信，那条会话里有几十条真实历史，
拿"清空会话"当清理手段，一次手滑就没了。

## 判据（先写死，不许跑完再定）

| 阶段 | 必须 |
|---|---|
| 没交付物就结单 | 400，理由是「工具一览里没有这张工单的交付物」 |
| 只传在线+下载 | `complete=false`、`missing=[视频讲解缺失]`、**不通知客户** |
| 三样不全就结单 | 400，理由点名缺哪样 |
| 补上视频 | `complete=true`，**自动让如意通知客户** |
| 再调一次上架 | `notified=false`（幂等，不重复打扰） |
| 客户侧 | 收到如意私信 + 站内通知；私信里写明「只有你看得见」 |
| 可见性 | 客户的工具一览里有它，另一个用户看不到 |
| 三样齐了结单 | 200 放行 |

## 实测记录

2026-09-09：18 项全通过。

跑之前踩到的三件事，都记在这里免得下次重来：

1. **结单前面还有既有闸门**（必须有关联项目 + 子任务全完成）。不补上这两样，
   我的交付判据根本轮不到执行——第一版"验"到的全是别的闸门在说话。
2. **幂等标记原来用 slug**，而 slug 从工单号派生：工单删掉后当天新建的工单
   拿到同一个号 → 同一个 slug → 新交付撞上旧消息，通知被"幂等"掉，
   客户永远收不到。改用工具 Id（自增，不复用）。
3. **`docker cp` 出来的库快照不含 WAL**，查不到刚写进去的私信——
   要查实时数据得走接口，不是查快照。

## 回滚点

1. **代码**：`git revert` 本次 P1 提交。回滚后结单闸门退回原来的
   「客户私信里含 deliverables 字样」，上架端点消失——**但已经上架的交付物不受影响**，
   它们只是普通的私有工具行（P0 那套仍在）。
2. **数据**：本次不加表不加列，没有数据要回滚。已建的交付工具行如需撤下，
   后台把 `IsPublished` 置 false 即可，或直接删该工具。
3. **半途失败怎么办**：上架端点是幂等 upsert，重复调用安全；
   通知只在三样齐的那一次发且只发一次，回滚代码不会导致重复通知。

**已演练**：本实验完整跑通"建单→收款→建项目→上架两次→通知→结单"，
再把工具、文件、财务记录、项目、子任务、工单、测试私信全部删回，
线上工具数 99→100→99、uploads 119 个文件不变（2026-09-09）。
