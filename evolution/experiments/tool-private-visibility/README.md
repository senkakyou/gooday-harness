# experiments/tool-private-visibility · 私有交付物的越权验证

## 要验证的改动

定制需求的交付物直接进工具一览，但**只有提需求的人看得见**（`docs/decisions/005`）。
要验的是这句话在四个身份下都成立：所有者、另一个登录用户、匿名、站长。

## 关联的 Decision

`docs/decisions/005-delivery-as-private-tools.md`

## 验证方式

**前后对比不适用，这是安全边界，只能实测**：建一个真的私有工具，
用四个身份逐条去打列表 / 详情 / 在线版 / 视频 / 下载 / 静态直链 / 可见性开关。

```bash
python3 evolution/experiments/tool-private-visibility/check.py
```

脚本自己不建数据（避免留垃圾）；跑之前先按注释建好一件测试工具，跑完删掉。

## 判据（先写死，不许跑完再定）

| 身份 | 列表 | 详情 | 在线/视频/下载 | 改可见性 |
|---|---|---|---|---|
| 所有者 | 看得到 | 200 | 200 / 206 / 200 | 可以 |
| 另一登录用户 | 看不到 | **404** | **404** | **404** |
| 匿名 | 看不到 | **404** | **404** | — |
| 站长 | 看得到 | 200 | 200 | 可以 |

外加三条：

1. **静态直链 `/uploads/private/...` 一律 404** —— 这是"私有"两个字的全部依据。
   不拦的话文件就是公开的，只是没人知道路径；而路径会出现在浏览器历史、日志、转发的链接里。
2. **不可见时返回 404 而不是 403** —— 403 等于承认"这个 slug 存在"。
3. **切成公开之后，详情给的仍然是鉴权接口地址** —— 文件还在 `private/` 目录下，
   静态层照样拦死。第一版按可见性判断怎么给地址，结果"公开之后反而谁都打不开"，
   这一条就是为它加的。

客户改不动站方工具）。后台文件列表里三个私有文件均判定为「在用」，

## 回滚点

这套改动分两段，回滚方式不同：

1. **代码**：`git revert b6705a5`。可见性判定、鉴权取文件、静态拦截都在这一个提交里。
   回滚后工具一览退回"全公开"，站方 103 个工具不受影响（它们 `OwnerUserId` 为 null）。
2. **数据**：迁移 `20260909000001_AddToolOwnerVisibility` 加的是三个可空/带默认值的列，
   **回滚代码不必回滚数据库**——列留着不影响旧代码。真要退，
   `Down()` 里三条 DropColumn 是完整的。

**已演练**：本实验建过一件真的私有工具、跑完 30 项、再删除工具与文件，
线上工具数从 99 → 100 → 99 复原（2026-09-09）。
