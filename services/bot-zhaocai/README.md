# services/bot-zhaocai · 招财（AI 财务）

轮询私信，回答站长的财务提问、确认收款。**只服务站长。**

从旧 `zhaocai_bot.py`（665 行）重新设计。**这是迁进新架构的第一个 AI 员工。**

## 职责

- 收款确认：站长说收到某笔款，记账并推进工单开工
- 财务汇报：回答收入、支出、待收款的提问
- 应收提醒：发现长期未收款的工单主动提示

## 明确不做

- 不接触客户（出口白名单只允许发站长与调度中心）
- **不改任何非财务状态**——工单流转、开发进度不归它管
- 不帮任何人写代码、执行脚本、操作数据库

## 从旧版改了什么

| 旧 | 现在 |
|---|---|
| prompt 硬编码在 .py 里 | 提到 `prompt.md`，改一句话不必动代码 |
| **prompt 里没有注入防御条款** | 补上完整六条铁则 |
| **没有「资金判定永不自愈」的硬约束** | 写进 prompt 的财务专属铁则 |
| 底层设施各 bot 抄一份 | 走 `packages/botkit` |
| 让模型自己查数据库 | **系统先查好事实注入 prompt** |
| 无 Task/Event | 每轮 ＋ 每次处理都留痕 |

**「系统先查好事实」这条重要**：退役的旧 bot 让模型在沙箱里自己跑 `sqlite3`，
而沙箱里命令可能不可用——它会跳过查询**靠记忆编造**。
数字型的幻觉在财务场景最危险。

## 只读模式（迁移期用过，现为 active）

`mode: readonly` —— 算出来但**不发不写**。
迁移期两套 bot 并存时必须用它：**两个财务同时对同一笔款入账是灾难**。
当时读数据库也绝不标已读，否则会把旧 bot 的活抢了。

> **那条「绝不标已读」后来自己变成了故障。** 旧 bot 2026-09-07 退役后
> 没人关掉它，于是每轮轮询都把同一条未读当新消息重答——
> 站长一句「你好」被回了 14 条，而心跳、服务状态、巡检全绿。
> 防护措施活过了它该在的时期，自己变成了故障。见 `packages/botkit/runner.py`
> 的 `mark_read()`。

切换：`config.json` 的 `mode` 改 `active`，不必改代码。

## 安全

**出口白名单是结构性防线**：只能发站长(1)与调度中心(20)。
即使招财被 prompt 注入说服了要给外部账号发消息，**它也发不出去**——
这不依赖模型的判断力。

*2026-09-07 实测：→站长 ✅、→调度中心 ✅、→普通用户 ⛔、→任意外部 ⛔、
未登记角色默认拒绝 ⛔。*

## 判据

1. **只读模式下零发送、零写入。**
   *实测：启动即只读，回复只落 `reply_suppressed` 事件。*
2. **失败必给发送者回执**，基础设施错误另报 P0。
   静默吞掉 = 用户看到「发消息没人理」，而日志里一切正常。
3. **心跳每轮更新**——不写的话「没消息」和「卡死」长得一样。
   *实测：08:35:20 写入正常。*
4. 财务事实由系统查好注入，**模型不自己查库**。
   *实测：本月收入/待收款/待收笔数三项查询正常。*
