# services/&lt;名字&gt; · 一句话说明它是什么

> **本文件是模板。** 新增服务：
> ```bash
> cp -r services/_template services/<名字>
> ```
> 然后改本文件、`main.py`、`deploy/unit.service`。
> **不需要动 `ops/install.sh`，也不需要动任何现有文件**——
> 安装脚本会自动扫描 `services/*/deploy/`。这是 G04 的要求。

## 职责

它做什么。一段话说清。

## 明确不做

比"做什么"更重要。角色越界是这套系统最常见的故障源
（历史上执行层自己又判了一遍路由层已经判过的事，连炸三轮）。

## 依赖

- 库：`packages/xxx`
- 外部：数据库 / 某 API / 某文件
- **状态写哪**：`/var/lib/gooday-harness/state/<名字>/`（G01，不许写进本目录）
- **日志写哪**：`/var/log/gooday-harness/<名字>.log`（G01）

## 判据

必须可证伪。带数字和时间窗。写不出来说明你不知道它算不算成功。

1. 例：**心跳文件 12 分钟内必有更新**，超时即视为卡死并重启。
2. 例：**处理失败时发送者 100% 收到回执**，静默吞掉记为故障。
3. 例：**连续 7 天无人工干预**。

## 演练

服务上线前必须做过，勾掉才算数：

- [ ] `kill -9` 后被自动拉起
- [ ] **停写心跳后被发现**（和上一条**不是同一回事**，systemd 只管进程死，管不了活着卡死）
- [ ] 依赖不可用时（数据库锁 / 凭据失效）给出**明确回执**而非静默失败
- [ ] 改代码后确认**进程启动时间晚于文件 mtime**，否则你验的是旧代码
