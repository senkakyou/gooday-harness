# services/bot-lingxi · 灵犀（COO / 站长秘书）

回答站长提问、组织审批、汇报全局。

## ⚠️ 全系统权限最大的角色

它有 **Bash、文件读写**，能操作数据库和服务器。
所以对它来说，**注入成功 = 攻击者拿到 shell**。

旧版 prompt 里注入防御条款是 **0 处**——这是今晚查出的洞里最危险的一个。

## 三条只对它成立的约束

**① prompt 里不写具体路径。**
旧版写了 **16 处**：数据库绝对路径、`.env` 位置、`JWT_SECRET` 在哪。
对一个有 Bash 的角色，那等于**把攻击面写进它自己的提示词**。
现在 0 处，那些进 `config.json`。

**② 工具权限走配置，不写死在代码里。**
不同环境该给的权限不同，而且改权限应该是一次**可 review 的配置变更**。

**默认移除了 `WebFetch` / `WebSearch`**（旧版给了）——
它们会把外部不可信内容直接引入一个**有 Bash 的会话**，那是注入的最短路径。

**③ 只服务站长。**
不是礼貌问题，是「**谁能驱动一个有 shell 的角色**」的问题。

## 判据

1. prompt 里**零处**具体路径/密钥位置。*实测：0（旧版 16）。*
2. 工具清单来自 config，代码里不出现硬编码的工具名。
3. 只读模式下零发送零写入。*实测：启动即只读。*
