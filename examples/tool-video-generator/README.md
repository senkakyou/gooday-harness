# tool-video-generator —— 给工具做动画讲解视频

工具详情页的第三条动线是「视频讲解」（见 `docs/decisions/004-tool-video-and-folder.md`）。
这里是首批三条讲解片的生成器：**场景脚本 → 配音 → 逐帧渲染 → mp4**，
纯本地跑，不依赖任何大模型。

首批成品（2026-09-08 上线，下载量前三的工具）：

| 工具 | 时长 | 体积 | 位置 |
|---|---|---|---|
| 小飞机 | 44s | 1.0MB | `uploads/tools/小飞机/讲解.mp4` |
| 魔兽搭建手册 | 57s | 1.3MB | `uploads/tools/魔兽搭建手册/讲解.mp4` |
| 视频拉取 | 64s | 1.6MB | `uploads/tools/视频拉取/讲解.mp4` |

## 怎么跑

```bash
python3 -c "
import asyncio, engine, scripts
asyncio.run(engine.build(scripts.PLANE, './out-xiaofeiji'))"
```

依赖：`edge-tts`、`playwright`（chromium）、`ffmpeg`。一条约 2~4 分钟（逐帧截图是大头）。

## 判据（可证伪）

1. 成品能被 `ffprobe` 读出时长和音视频两条流，且时长 ≥ 40 秒。
2. 画面里的中文**不是方块**——这是本项目实际踩过的坑：
   文字必须在浏览器里排版，交给 ffmpeg 的 `drawtext` 会因缺中文字形出方块。
3. 旁白说完那一句时，画面还没切走（每幕时长 = 配音时长 + `TAIL`）。
4. 同一个 `t` 渲染两次得到同一帧（`seek(t)` 是纯函数，不用 CSS 动画）。

## 三个设计取舍

- **先配音、再定时长**：旁白多长这一幕就多长。反过来做，话会被切断，
  或者画面停着干等。
- **动画由 `seek(t)` 驱动，不用 CSS 动画**：截图是一帧一帧来的，
  CSS 动画按墙上时钟走，截图快慢会让画面抖。
- **内容只讲工具真有的东西**。`scripts.py` 里「视频拉取」那一幕专门花 8 秒说
  「网页只是演示、要下载到本机才能真下」——工具本身就是这样，
  片子替它吹成在线可用，用户点进去只会觉得被骗。

## 没做成 workflow 的原因

它是**一次性内容生产**，不是定时任务：什么时候给哪个工具做讲解，是人挑的。
将来如果变成「每周给新上架工具自动出一条」，再按 `workflows/_template` 立成员。
