# workflows/cert-renew · TLS 证书续期

每天 02:30 检查一次。`certbot renew` 只在证书 <30 天时真续，否则空跑——
每日跑是标准做法。

## 换来它的事故

源证书由 certbot 签发但**从无定时续期**，月中静默过期。
nginx 443 和 xray 555 共用同一张证书，一起爆。

**证书过期是最典型的「安静地烂掉」**：没有任何东西会报错，
直到某天所有人的浏览器同时开始报警。

## 比旧脚本多的一样：读实际到期日

旧脚本只看 `certbot` 的退出码。**但 certbot 空跑也返回 0**——
于是「续期失败」和「还没到该续的时候」在退出码上长得一模一样。

新版续期前后各读一次**实际生效证书的到期日**（走 TLS 握手，
读的是浏览器真正看到的那张）。certbot 说什么不算，实际到期日才算。

到期日仍低于 `warn_days` = 续期没起作用 → **P0**。

## 跑

```bash
cp config.example.json config.json
python3 run.py
```

*2026-09-07 实测：读到 www.gooday.ltd 还有 68.7 天到期。*

## 判据

1. **判据必须是实际到期日，不是 certbot 退出码。**
   否则「续失败」会伪装成「不需要续」。
2. 续完后实际到期日 < `warn_days` → P0 并非零退出。
3. 读不出证书也报 P1——读不出和没问题是两回事。

## 停摆判定

`/var/log/gooday-harness/cert-renew.log` 超 48 小时无新内容 = 停摆。
另有 `workflows/patrol` 的证书检查作为独立兜底——
**续期和监控必须是两条腿**，续期挂了监控还能喊。
